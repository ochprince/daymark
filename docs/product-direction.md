# Daymark · 刻度 —— 产品方向备忘

> 记录用户 2026-10-21 提出的八条想法，以及对这些想法的拆解、张力与取舍。
> 这是方向讨论稿，不是排期；任何一条落地前仍需单独过方案。

## 一、原始想法（照抄，不改写）

1. 女性向用户
2. 卡通可爱风
3. 主题自定义
4. 注意力的聚焦，一次只能聚焦在一个打卡或重要事件上
5. 横向滑动切换风格，而非删除事件，删除是使用频率较低的动作
6. 结合 AI 自定义背景图像
7. 允许上传相片作为事件的背景
8. 深挖情绪价值

### 更正（2026-10-21，用户当场修正）

- 「女性向」说重了。实际定位是**中性偏可爱卡通的萌系审美，男女通吃**。
- 明确否掉「粉色 + 手写体」这种刻板做法，原话「太烂了」。
- 目标不是单一风格，而是**多套主题风格一网打尽**；首套以可爱卡通为主。

这条更正把整批想法的重心从「讨好某个性别」挪回「造型可换」：定位是**中性的、有亲和力的工具**，
可换的是皮肤，不是人群。

## 二、先分清「定位」和「皮肤」

这八条不在同一个层面，混在一起会互相打架：

- **定位层**：1（中性萌系）、8（情绪价值）——决定产品对谁说话、说什么话。
- **皮肤层**：2（卡通可爱）、3（多套主题）、6（AI 背景）、7（相片背景）——决定长什么样。
- **结构层**：4（注意力聚焦）、5（横滑与删除）——决定信息和手势怎么组织。

皮肤层可以随时换；定位层一旦改，文案、动效、字体、色彩、甚至功能取舍都要跟着改。**先定定位，皮肤才有意义**，否则会做成「工具骨架 + 粉色外壳」，两头不讨好。

## 三、逐条拆解

### 1. 中性偏萌系（原写「女性向」，已更正）

**已否掉的偷懒解读**：可爱 ≠ 粉色 + 手写体。这套符号既过时也筛人。

正确理解是**萌系作为造型语言**：圆润的形状、有生命感的角色与表情、柔和的动势、拟人化的物件
（例如把「连续 6 天」画成一颗慢慢长大的东西）。配色只是其中一环，且不必走粉。

对功能和文案，仍然保留四条判断标准（它们不依赖性别）：

- **是否承认情绪**：允许说「今天很糟」，而不只是「你今天没打卡」。
- **是否去绩效化**：断了、放弃一轮，不被惩罚或羞辱（红字、断签、排名）。
- **造型本身算功能**：字体、留白、封面、语气，不是装饰。
- **是否可分享**：分享是这类产品最自然的传播路径，而当前应用**没有任何可分享的产物**。

这条真正的含义是：**把「记录工具」往「陪伴物」挪**；而萌系是陪伴感最直接的载体。

### 2. 卡通可爱风（首套皮肤）

与当前审美（深色、几何、Inter、克制）是两个人格，不是微调。

可行的做法不是二选一，而是**风格包（Theme Pack）**：同一套信息结构，皮肤层可替换。

- 需要先抽象出「皮肤」接口：色彩令牌、圆角、字体、卡片材质、装饰物、背景、动效曲线。
- 现在的 CSS 变量体系（`--surface` / `--text-3` / `--radius-card` / accent 色板）已经是雏形，缺的是「一套皮肤 = 一份令牌文件」的组织方式。
- 风险：可爱风会削弱「大数字」的仪式感；需要在皮肤里单独设计数字的呈现（例如手绘数字 vs 现在的渐变数字）。
- 萌系的可动载体比配色更重要：卡片里那个小圆点、进度、连续天数，都可以被拟人化成「会长大的东西」。

### 3. 主题自定义（多套风格包，首套可爱卡通）

目标是「多套风格一网打尽」，不是给一套皮肤换颜色。所以入口形态也跟着变了：
需要一个**能看见多套皮肤、并能快速对比**的地方（见第 5 条）。

仍然不要做「几十个颜色任选」，那会稀释品牌，也让每次改版都要兼容全部组合。

建议做成 **有限风格包 + 有限可调项**：

- 风格包：如「萌系（首套）/ 夜刻 / 纸感 / 像素」4 套，每套是完整人格。
- 可调项：主色（从每个包的 3–5 个配色里选）、背景（纯色 / 相片 / 每日一图）、字号（标准 / 大）。
- 不开放任意取色——对比度会失控，这条项目已经踩过（浅色 `--text-3` 只有 3.35）。

### 4. 注意力聚焦：一次只有一个

这是**结构层的真命题**，也是这一批想法里最有产品价值的一条。

现状：三页并列列表，一屏能放 2–3 张卡，注意力是摊平的。

三种落法，取舍不同：

| 方案 | 形态 | 代价 |
|---|---|---|
| A 焦点卡模式 | 顶部一张大卡（用户指定的「今天的一件」），其余折叠成一行小条 | 改动最小，仍保留列表 |
| B 每日一问 | 打开只问「今天做了什么」，答完才看到其余 | 仪式感最强，但高频使用会嫌烦 |
| C 焦点轮换 | 由系统按「最久未记 / 最接近到期」自动挑出一张 | 不用用户维护，但会「替我决定」，容易误判 |

推荐 A 起步：**焦点由用户钉选**，其余收进一行可展开的列表。它同时服务了第 8 条（焦点卡可以承载情绪文案、背景图、相片）。

注意：聚焦和「多件事」不矛盾——聚焦的是**展示**，不是数据。别做成「只能有一个打卡」。

### 5. 横滑与删除：两个都要重做

用户补充：**首页的左滑删除很容易误操作**，换风格不要踩同样的坑。

判断：

- 左滑删除是坏设计——它在触摸屏上和「滚动 / 翻页」共享同一方向，误触率高，后果又不可逆。
- 删除是低频动作，不值得占用首页最高频的手势位。
- 换风格是另一种性质的动作：**低频、可逆、视觉冲击大**，它需要的是一个「看得见效果」的专门界面，而不是在首页留下一个滑动手势。

**删除的新落点**：编辑弹层底部（走过的日子已有「删除这个日子」，补到打卡与倒数日），三页一致。首页左滑直接撤掉，不给替代手势。

**换风格的新落点**（三选一，需拍板）：

| 方案 | 形态 | 取舍 |
|---|---|---|
| S1 皮肤画廊 | 顶栏一个色板图标 → 全屏画廊，每屏一套皮肤的实时预览 | 「多套一网打尽」最直观；预览要真渲染而不是截图，成本最高也最值 |
| S2 抽屉式切换层 | 从顶部下拉出横向卡片流，滑动预览、松手应用 | 保留了「滑动换风格」的乐趣，又与首页手势隔离 |
| S3 设置项列表 | 设置里一个列表，点选即换 | 最省事，但完全没有「哇」的体验，浪费了这个功能 |

推荐 **S1**：它不是「设置项」，而是一个可以逛的地方——正好承接第 3 条「一网打尽」和第 8 条「情绪价值」。
滑动预览只在画廊内部存在，与首页翻页互不干扰。

### 6. AI 自定义背景

与当前「无后端、无账号、纯前端」的架构正面冲突。四条路：

- **BYO Key**：用户自带 API Key，存在本机。风险：key 暴露在浏览器、跨域、失败体验；但零成本。
- **服务端代理**：一个 Cloudflare Worker 转发（仍是「无账号」，但「有后端」）。最实用，代价是运维与费用。
- **预生成素材包**：官方挑选几十张 AI 图打包，按风格包分发。零架构改动，但没有「自定义」。
- **本地程序化生成**：用 canvas/WebGL 生成抽象背景（渐变、噪点、流动）。完全离线、零成本，且和「刻度」的几何气质一致；缺点是不是用户想象的「AI 画一张」。

推荐组合：**先做本地程序化生成（立刻可用）→ 再加 Worker 代理的 AI 生成（需要你决定是否接受一个后端）**。

### 7. 上传相片作为背景

技术上可行，但要先解决存储，这是硬约束：

- localStorage 只有 ~5MB 且同步写，放不下照片。**必须引入 IndexedDB**（`idb` 或无依赖的薄封装）。
- 上传后在 canvas 里压到长边 1600px、JPEG q≈0.8（约 150–300KB/张），并生成一张 40px 的模糊缩略图做占位。
- 需要「清理/替换/删除图片」的入口，否则用户会在某天突然写不进去（配额满）。
- 相片会直接影响文字可读性 → 必须强制加一层随图取样的遮罩（同现在的 `--scrim` 思路），对比度要按「最坏情况」（亮图）验一遍。

### 8. 深挖情绪价值

这是 1–7 的总纲。可以落地的方向：

- **语言**：现在的文案偏工整（「按住卡片记一次」「已经走过的日子」）。情绪价值来自具体的、非功能性的句子，例如「今天也可以什么都不做」。
- **被看见**：记录本身要被「回应」——第 7 天、第 30 天、断签后回来，各有一句话，而不是只有数字。
- **结束的仪式**：一轮结束时（重置/删除/到期）给一次告别，而不是一条 toast。
- **可分享的产物**：一张卡片截图（背景 + 数字 + 一句话），这是这类产品最重要的传播单元。
- **不要做的**：排行榜、连续天数惩罚、红色警告。它们和「陪伴」是对立的。

## 四、依赖关系（先做什么）

```
风格包体系（皮肤接口）
   ├── 2 卡通萌系 ─┐
   ├── 3 多套主题   ┼── 5 皮肤画廊
   └── 6/7 背景     ┘
焦点卡（4）
   └── 承载 8 的情绪文案与背景
IndexedDB（7 的前置）
   └── 相片背景 → 分享截图
```

结论：**风格包体系是这一批想法里唯一的基础设施**，不做它，2/3/5/6/7 都会变成散装特判。

## 五、优先级建议

- **P0（先做）**：撤掉首页左滑删除、删除统一进编辑弹层；风格包抽象（不含新皮肤）；IndexedDB 与图片管线。
- **P1**：第一套萌系皮肤、皮肤画廊（S1）、分享截图、情绪文案重写。
- **P2**：AI 背景（取决于是否接受 Worker 代理）、焦点卡模式。

## 六、待拍板

1. 换风格入口走 S1 画廊 / S2 抽屉 / S3 设置列表。
2. 是否接受一个后端（Cloudflare Worker）来承载 AI 生成。
3. 撤掉左滑删除这一步，现在做还是等风格包一起做。

## 七、方法：用 REA 拆经典 App

想法（2026-10-19）：用 REA 这类逆向工具分析经典 App，把好的设计借鉴过来。

结论：**能用，但只值「交互层」那一层** —— 手势仲裁顺序、动效常数、空/失败态文案。视觉层截图取色就够，意图层永远拿不到。
